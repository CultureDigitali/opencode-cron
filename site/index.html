    Technical specifications

    Everything answered directly without accordion toggles.

    Does it require a cloud subscription?

    No. Everything runs completely locally on your machine via standard operating system daemons (launchd on macOS, systemd on Linux, Task Scheduler on Windows) and local JSON persistence.

    How does it interact with running OpenCode sessions?

    It connects directly to OpenCode sidecar HTTP transport using rotating credentials and session tokens, preserving continuity across turns without restarting agents.

    What happens if a prompt fails?

    The Dead Letter Queue intercepts consecutive failures, trips the circuit breaker to prevent token waste, and quarantines the job until reviewed in the Web GUI or CLI.

    Can jobs trigger each other?

    Yes. DAG pipelines allow defining upstream and downstream dependencies with optional memory payload passing and cycle detection.

    How is context memory handled?

    Each job maintains persistent memory in .opencode/cron/memory/, summarized and pruned on each turn to preserve token limits without losing state.

    Is there a graphical user interface?

    Yes. A full Web GUI and cross-platform desktop application runs on localhost:4488 with live logs, priority queues, and token inspection.
