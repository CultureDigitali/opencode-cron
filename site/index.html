The problem

Plain cron is blind.

Classic schedulers fire a shell script and forget. opencode-cron re-runs an intelligent agent with full memory and judgment.

😵 Plain cron / bash loops

  • ✕Spawns blind one-off shell scripts - zero context
  • ✕Conversation state wiped on context compact
  • ✕Repeats the same alert every single tick
  • ✕Can loop forever and burn your API tokens
  • ✕Terminal only, grepping obscure syslog files

⚡ opencode-cron

  • ✓Re-prompts the same session ID with full history
  • ✓Compaction hook re-injects the memory file
  • ✓seenHashes dedup prevents repeat alerts
  • ✓60s min, jitter, maxRuns and 5-fail circuit breaker
  • ✓Mission Control Web GUI + execution timeline

Architecture

How it works

Four steps from a scheduled job to an intelligent, memory-aware tick.

Schedule

cron_add stores a job in jobs.json plus a memory file - bound to your session ID.

Fire

An in-process timer (or a 60s OS daemon when the TUI is closed) wakes the due job.

Remember

The tick prompt injects a frozen objective + memory + a 3-question self-check + your follow-up.

Act

The same session continues; findings persist to markdown and dedupe against seenHashes.
